Same model, wildly different prices.

The identical model id is hosted by dozens of providers, with up to a 100x spread on the same workload. And for agent traffic, most tokens are cache-reads, so list prices are misleading: only blended cost under your real token mix tells the truth.

Blended $/M

Pricing that matches your usage

Every model × provider endpoint is priced as input + cache + output, weighted by your actual token mix. A provider that's cheap on input but burns your cache bill can never win.

Health gates

Cheap, but alive

Throughput p50 ≥ 45 tps and uptime ≥ 99% are hard requirements. The cheapest endpoint nobody can actually call is worthless; PennyRoute never picks it.

Fallback chains

Free first, then cheapest paid

Ordered pipelines like free :free → cheapest. The engine walks top → bottom and uses the first healthy step. Per-request failover retries the next candidate on error.

Measure once, route forever.

Live pricing from OpenRouter's endpoint stats: zero benchmark calls, zero tokens burned. The engine re-checks every few minutes and switches your config automatically.

1

Build your watchlist

Pick models from the full OpenRouter catalog. PennyRoute fetches every provider's live pricing, latency, throughput and uptime.

2

Rank by blended cost

Each endpoint gets a blended $/M under your mix, gated on health. The ranking is recomputed live, no stale numbers.

3

Route, and fail over

Requests hit one OpenAI-compatible endpoint. The primary chain picks the cheapest healthy provider; on error the next candidate serves.

# data/chains.json — ordered pipeline
{
  "name": "main",
  "primary": true,
  "entries": [
    { "type": "cheapest", "filter": ":free" }
    { "type": "cheapest" }
  ]
}
# python — any OpenAI-compatible client
from openai import OpenAI

client = OpenAI(
  base_url="http://your-host:8490/v1",
  api_key="pnk-…")
r = client.chat.completions.create(
  model="penny",
  messages=[{"role": "user", "content": "hello"}])
print(r.model) # who actually served you
